# Rookie100 前期课程设计包

范围：现有 early 阶段 q01–q14，基于 Phase 4A。

解压后打开 `index.html`，在左侧选择任务，可搜索“水”“气体”“食物”等关键词。

- **查看准备**：因果关系、前置资源、操作步骤和按钮行为。
- **查看示例**：资源流程图与功能分区布局图，可分别保存。
- **检查设施 · 设计**：拟采用的验收、失败反馈及测试场景。这里只浏览设计，不会读取游戏或模拟一个“检测通过”的结果。
- **打印当前任务**：打印当前任务的三个内容区。

`DESIGN.md` 是完整文字稿；`tasks.json` 是结构化设计数据；`figures/` 包含 28 张 SVG 图。

所有布局图都是概念功能分区，不是实机截图，也不是已验证的逐格施工蓝图。复杂管线、高压制氧、冷却、辐射等方案的精确接法需要后续游戏内验证，不能按这些分区框直接照建。流程图说明依赖，不承诺精确配比。

标题为建议的课程标题。除现有 q01 基础可用性、q03 运行和诊断等已有功能外，新判定均有实现状态标记；本设计包没有批量修改游戏任务，也不是新的模组安装包。不要把它覆盖进游戏模组目录。

## 通用按钮契约

1. 查看准备：只读，不要求先完成本任务才能查看所需知识。材料精确数量、科技 ID 与环境阈值从当前游戏配置获取，不靠文案猜测。
2. 查看示例：先显示原理图；真实布局截图需记录游戏版本、DLC、视图、关键方向及一次成功运行证据，再标为“经验证示例”。未验证图始终保留显著标记。
3. 检查设施：游戏实现时必须显示检查对象、范围、时间和未检查项。点击读取新状态；不代替玩家建造、启用、运送或修改优先级。尚无检测器时不显示虚构的成功结果。

验收状态统一区分：未满足、已满足、无法确认、需人工观察。成功诊断某台设备不自动证明整个基地稳定；全局建筑数量不代替同一系统内的连接证据。

## 分批实施

- A：巩固 q01、q03 已有基础判定和反馈。
- B：q02 指南可达性、q04 具体科研条件。
- C：q05 从供排水可用到实际使用，再到回用。
- D：q06/q08 实际作物与食物链。
- E：q07/q09/q10 电路及气体系统关系。
- F：q11–q14 生产行为、效果证据与区域关系。

每批冻结基线、限制差异、测试、产出安装包及回滚包。保留任务 ID、旧领奖记录与奖励；新行为历史若跨读档保存，单独设计 schema 迁移。不得将这些设计状态作为新的平行持久化进度。
